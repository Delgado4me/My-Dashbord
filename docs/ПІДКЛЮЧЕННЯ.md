# Підключення My-Dashbord

Оновлено: 30.09.2026. Цей файл описує конфігурацію коду; запис у GitHub не означає, що серверні налаштування вже застосовано.

## 1. Зовнішній Supabase

Використовуємо наявний проєкт `My-Dashbord`. Його Project URL і publishable key з попередньої копії збережені в `public/config.js`. Це браузерні параметри, а не привілейовані ключі. Дані захищаються входом і RLS.

У Lovable відкрийте **More → Cloud → Already have a Supabase project? Connect it here**. Авторизуйте потрібну організацію Supabase та виберіть саме існуючий проєкт. **Enable Cloud** створює інший бекенд і для цього перенесення не потрібен. Підключення Lovable до GitHub саме по собі не підключає базу.

Після підключення перевірте, що Lovable показує правильний зовнішній проєкт. Не створюйте таблиці повторно, не копіюйте користувачів і не запускайте старі SQL-міграції пакетом. Поточні зміни структури БД не потребують.

## 2. Особистий вхід

На головній є кнопка «Увійти». Використайте свій наявний Supabase Auth-акаунт. Новий GitHub-акаунт не змінює цей обліковий запис.

У Supabase Authentication → URL Configuration додайте фактичну HTTPS-адресу застосунку Lovable до Redirect URLs. Якщо переносите основний вхід, перевірте також Site URL. Для тесту можна залишити попередню адресу дозволеною.

Публічні URL/key можна змінити через «Ще → Сховище → Налаштування підключення». Перевизначення діє лише в цьому браузері. Приймаються HTTPS Project URL на `*.supabase.co` та publishable/anon key. Secret key і service_role key форма відхиляє. Сесії різних Supabase-проєктів зберігаються окремо. Пароль належить тільки формі входу, не GitHub чи Markdown.

## 3. Серверні параметри

У тому ж зовнішньому Supabase, Edge Functions → Secrets, **спочатку** задайте параметри, потім розгорніть оновлені функції. Чинні значення Google OAuth та токена GitHub можна зберегти; не генеруйте нові без потреби.

| Назва | Значення |
| --- | --- |
| `DASHBOARD_SITE_URL` | Основний HTTPS-origin застосунку Lovable, без шляху, query чи fragment |
| `DASHBOARD_ALLOWED_ORIGINS` | Необов’язковий список точних додаткових HTTPS-origins через кому: preview, попередній сайт; без `*` |
| `DASHBOARD_OWNER_USER_ID` | UUID **наявного власника** з Supabase Authentication → Users |
| `DASHBOARD_GOOGLE_EMAIL` | Одна дозволена адреса Google, яку ви хочете підключити |
| `DASHBOARD_GOOGLE_CLIENT_ID` | Наявний Google OAuth Web application client ID |
| `DASHBOARD_GOOGLE_CLIENT_SECRET` | Наявний серверний client secret |
| `DASHBOARD_OBSIDIAN_REPOSITORY` | Джерело нотаток у форматі `owner/repository` |
| `DASHBOARD_OBSIDIAN_BRANCH` | Гілка джерела; типово `main` |
| `DASHBOARD_OBSIDIAN_PATH_PREFIX` | Необов’язкова папка, наприклад `notes`; порожнє значення дозволяє весь vault за правилами доступу |
| `DASHBOARD_OBSIDIAN_GITHUB_TOKEN` | Fine-grained токен, Contents: Read-only, лише для обраного репозиторію |

Шаблон: `supabase/functions/.env.example`. Реальний `.env` і секрети до Git не потрапляють. Вбудовані `SUPABASE_URL`, серверний ключ і публічний ключ надає саме Supabase; не підмінюйте їх реквізитами іншого проєкту.

`DASHBOARD_SITE_URL` — адреса відкритого застосунку, **не** `lovable.dev/projects/...`. Якщо старий сайт має ще працювати, додайте його origin до `DASHBOARD_ALLOWED_ORIGINS`. OAuth повертає на основну адресу `DASHBOARD_SITE_URL`.

## 4. Google: пошта і календар

Це окреме підключення після особистого входу, а не заміна Supabase Auth.

Використайте наявний Google Cloud OAuth client. Gmail API та Google Calendar API мають бути увімкнені. Потрібні дозволи `openid`, `email`, `gmail.modify`, `calendar.events`.

Точний Google Authorized redirect URI:

```text
https://<REF_ВАШОГО_SUPABASE>.supabase.co/functions/v1/dashboard-google-callback
```

Оскільки зовнішній Supabase залишається тим самим, callback не змінюється лише через переїзд frontend у Lovable. Змінюються дозволений origin застосунку та адреса повернення з callback. Якщо OAuth consent у режимі Testing, потрібна Google-адреса має бути серед test users.

Далі: відкрити застосунок за дозволеною HTTPS-адресою → увійти → «Ще → Підключити Google». Дозвіл підтверджуєте у Google. Пароль Gmail застосунок не запитує. Перевіряти цей крок краще в окремій вкладці застосунку, а не всередині preview-iframe редактора.

## 5. Останні нотатки Obsidian

Джерелом є GitHub-версія Markdown. Після локального збереження в Obsidian потрібен commit/push у джерело. Список показує час коміту, а не локальний час редагування.

Для перевірки **лише в дозволеному репозиторії**:

```text
DASHBOARD_OBSIDIAN_REPOSITORY=Delgado4me/My-Dashbord
DASHBOARD_OBSIDIAN_BRANCH=main
DASHBOARD_OBSIDIAN_PATH_PREFIX=notes
```

Тестовий файл — `notes/Початок.md`. Публічний репозиторій годиться для синтетичної нотатки. Для особистого vault потрібне його окреме приватне джерело або зміна видимості сховища власником. Асистент не отримує дозволу на інші репозиторії лише від налаштування джерела застосунку.

Якщо продовжуєте читати вже підключений приватний vault, збережіть його репозиторій, гілку й наявний read-only токен. Не міняйте їх на тестову папку без потреби.

У застосунку: «Нотатки → Obsidian». Є «Усі / Додані / Змінені», ручне оновлення, час перевірки, фаворити й окремий Markdown-читач. До 20 останніх унікальних нотаток; обмежена історія позначається як часткова. Службові папки, приховані шляхи, `node_modules` і `Haven` залишаються виключеними.

## 6. Розгортання функцій

Джерела оновлених функцій лежать у `supabase/functions/`; `.js` entrypoints явно задані в `supabase/config.toml`. Застосуйте їх до того самого зовнішнього проєкту після налаштування параметрів. Перевірка JWT збережена для Google API та Obsidian. OAuth callback публічний лише на рівні HTTP і перевіряє одноразовий стан, власника та Google-акаунт.

До розгортання server-side змін новий frontend не може сам змінити CORS або секрети живого сервера. Збереження форми підключення у браузері цього також не робить.

## Контроль після підключення

1. Вхід у наявний акаунт показує наявні нотатки й справи.
2. Google підключається до дозволеної адреси; лист відкривається повністю.
3. Нова тестова Markdown-нотатка видима після commit/push та «Оновити».
4. Невдале оновлення позначене помилкою й не стирає попередній список.
5. Вихід не скасовується запізнілою відповіддю refresh.
6. Повернення Google на кореневу адресу Lovable зберігає `?google=...` під час переходу до `dashboard.html`.
